# Evals and benchmarks

This page lists every measurement in this repository: what each one measures, where its results are, and how to run it again. It is for anyone judging Stint or checking its numbers. The numbers themselves are in [Claims at a glance](../docs/proofs.md#claims-at-a-glance), and `bun test packages/core/test/docs.claims.test.ts` fails when the README or `docs/proofs.md` quotes a number its results file does not hold.

A live run calls Meta models and needs the keys its folder's README names; the scripts under `scripts/` take a budget and stop before they would pass it. An offline run needs no key and calls no model.

| Measurement | What it measures | Results | Run it again |
|---|---|---|---|
| The packet benchmark, 27 October | Hand-over size, input tokens, cost and the daemon's verdict when the next agent continues from the packet or from the transcript | [`bench/README.md`](../bench/README.md), `bench/results.json`, `bench/runs/` | Offline: `stint bench --replay --tasks 2 --modes transcript,packet`. Live: `stint bench --tasks 5 --modes transcript,packet` |
| The fair hand-off rerun, 2 November | The same from one shared first run per task, graded by held-out tests, with the task and the diff as a third arm | [`bench/fair/`](../bench/fair/README.md) | Offline: `bun scripts/fair-bench.ts --account-only` rebuilds the results from the recorded runs. Live: `STINT_LIVE=1 bun --env-file=<your env file> scripts/fair-bench.ts --budget-usd 8 --repeat 2` |
| The unfinished hand-off rerun, 2 November | The same from checkpoints that fail their held-out tests, with the first agent resuming its own session as a fourth arm | [`bench/fair-unfinished/`](../bench/fair-unfinished/README.md) | Live: `scripts/unfinished-bench.ts checkpoint`, then `continue`, as its README says |
| The relay, 29 October | One task carried by Muse Code, Claude Code and Codex in turn on three public repositories Stint had never seen, graded by hidden tests | [`bench/relay/`](../bench/relay/README.md) | Offline: `bun test scripts/test/relay.test.ts` runs a dry relay and checks every published run. Live: `bun scripts/relay.ts <repo> --budget-usd 40` |
| The scorecard, 29 October | Single runs by the Stint agent on Muse Spark Open, with no hand-off, graded by the relay's hidden tests | `bench/scorecard.json`, [the scorecard](../docs/proofs.md#the-scorecard) | Offline: `bun scripts/scorecard.ts --dry`. Live: `bun scripts/scorecard.ts --budget-usd <usd>` |
| The review recheck, 2 and 3 November | Whether a reviewer flags the graded patches the hidden tests failed and approves the ones they passed: Muse Spark 1.3, and Muse Glimmer 30B with the whole diff | [`bench/review-recheck/`](../bench/review-recheck/README.md) | Live: `STINT_LIVE=1 bun --env-file=<your env file> scripts/review-recheck.ts --reviewers meta-api/muse-spark-1.3,ollama/muse-glimmer:30b-mlx --budget-usd 1.5`; Glimmer alone needs no key and costs nothing |
| The visual set, 2 November | Whether the visual check fails a page with a seeded defect and passes a clean one, on ten pages, and whether SAM 3.1 boxes the defect | [`bench/visual-set/`](../bench/visual-set/README.md); the single check of 29 October is in `bench/visual/` | Live: `STINT_LIVE=1 bun --env-file=<your env file> scripts/visual-set.ts --budget-usd 0.75` |
| The golden tasks | Tasks that must keep passing, k tries each, graded by the daemon's verification and the task's scenarios (pass^k) | `bench/golden/`, `bench/golden-results.json`, `bench/golden-runs/`; [`docs/evals.md`](../docs/evals.md) | Offline: `stint eval --golden --k 3 --replay`. Live: `stint eval --golden --k 3` |
| Skill evals | Whether a learned skill helps on the tasks it names before it leaves probation | [`docs/evals.md`](../docs/evals.md) | Offline: `stint eval --skill <name> --replay`. Live: `stint eval --skill <name>` |
| The quickstart | Seconds from a clean clone to the replay, measured by CI | `bench/quickstart.json` | Every push, in the `quickstart` job of `.github/workflows/ci.yml` |

Each folder's README says what was live, what was scripted, what failed and what the results do not show. A published run is never replaced, so a failed one stays published.
