# R-069 · The judge path: try it in a browser, see the evidence first

Day: 6 (30 Oct) · Owner: CC · Depends on: R-022 (demo), R-028 (MCP), R-059 (README), R-065 · Fallback: README table and the bootstrap change only · Cut order: 2

## Goal
A judge gives a project minutes, not an afternoon. Today Stint asks for Bun, a clone and, with Ollama installed, a 19 GB download before anything shows. Rival entries offer a hosted console and a README that maps each judging criterion to its evidence. This spec gives Stint a zero-setup path: a read-only copy of the board, published on GitHub Pages, that plays the recorded story in the browser with no daemon and no keys; a README whose first screen maps the four judging criteria to evidence; a quick start that downloads nothing it does not need; one-line setup to use Stint from Claude Code and Codex over MCP; and the demo shows several agents switched on.

## Requirements
1. **Static board.** `bun run build:judge` builds the web app in a static mode: every GET the UI makes is served from a snapshot of a finished replay (JSON files generated by crawling the replay daemon's API for every route, task and tab), live updates are off, and every action that would change something is disabled with the reason "This is a read-only copy of the recorded story. Install Stint to run it." The replay strip still says "Replay, hand-written". Deep links work through a 404.html fallback. Output in `dist-judge/`.
2. The snapshot generator is a script with a test that the snapshot covers every GET path the board, T-0040, T-0042, T-0043 (each tab), Factory, Skills and Goals request.
3. **Publish.** A GitHub Actions workflow builds `dist-judge/` and deploys it to GitHub Pages on a push to main. Publishing happens only after the owner has looked at the local build.
4. **README first screen:** one line on what Stint is, the judge page link, then a table: Impact, Use of Meta AI, Technical depth, Demo, each with the evidence and a link (proofs, scorecard, tests, video). Then "Where Meta's models are used": one row per model (Muse Wonder, Muse Spark 1.3, Muse Spark Open, Muse Glimmer, SAM 3.1, Muse Code) with its job and where to see it. Then "Built during the hackathon" with dates and a works / not yet table.
5. **Quick start downloads only what it needs:** bootstrap no longer starts the Glimmer pull by itself; `--with-glimmer` does, and the message says what the offline review needs.
6. **MCP one-line setup:** `stint mcp install claude` and `stint mcp install codex` register Stint's MCP server with each tool (through their own CLIs: `claude mcp add`, and Codex's config), print what was changed, and `--print` shows the command without running it. Docs give the one-liners.
7. **Agents on in the demo:** the demo's config enables Claude Code and Codex alongside Muse Code and the Stint agent, each set to a Meta model (Claude Code on Muse Glimmer through Ollama, Codex on Muse Spark 1.3 through the Meta Model API), so the board's agent list shows four agents. Defaults for a new repository are unchanged (ADR-0004).

## Acceptance
1. The snapshot coverage test passes; a browser test opens the static build and checks the board, a task's tabs, Factory and Skills render with data and that Approve is disabled with the reason.
2. `bash scripts/bootstrap.sh --check-only` on a machine with Ollama and no Glimmer prints the opt-in line and starts no download (test with a fake `ollama`).
3. `stint mcp install claude --print` and `codex --print` print the exact commands (tested).
4. The README's first screen holds the criteria table and the models table; `scripts/test` checks every link in them resolves to a file or a URL in the repository.
5. `bash scripts/check.sh` and `bun run test:ui` pass.
